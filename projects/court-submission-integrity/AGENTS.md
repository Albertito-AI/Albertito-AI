# Development boundaries

Read README.md, RIGHTS.md, docs/THREAT_MODEL.md, docs/VALIDATION.md and the current
roadmap before changing this program. Check current remote state before any future
GitHub work. Use focused branches, complete diffs, exact-revision checks and guarded
merges. Do not claim human review when the reviewer is an agent.

This is a distinct owner-requested project. Do not modify another portfolio's
licence, create a scheduler, change financial records, revive Sparks, contact
courts or integrate real case systems through this code task.

Use original fictional data for development. Preserve source identity, exact
locations, input immutability, explicit unknowns, unsupported-input failures,
zero-network defaults and the distinction between source presence and support.
Never change a match into a truth, admissibility or merits certificate.

No hosted CI, model calls, hosting purchases or other metered operation may be
activated without a verified authorised resource envelope. No CI workflow is
included in this alpha. Do not resolve that by changing private-data visibility.

Run the unittest suite and complete CLI examples. Record actual environment,
failures, skipped checks and limits. Local tests are not independent adoption or
court approval. Obtain separate authority for real documents, authenticated
integrations, production deployment and any external communication.
