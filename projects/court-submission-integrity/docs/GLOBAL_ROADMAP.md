# International roadmap and evidence gates

**Principle:** global architecture; local legal and institutional validation.
No calendar, funding, procurement access or court participation is assumed.
No outreach, contract, invoice, deployment or external integration was undertaken.

## Gate 0: inspectable local kernel | prepared

Deliver a deterministic, structured-input checker and report with fictional
examples. Record exact tested environment and limits. No paid API or hosted CI.
Present alpha scope accurately. Local tests do not establish judicial usefulness.

## Gate 1: first useful document workflow | limited intake prepared; source resolution next

Choose one document type and jurisdiction, preferably a civil written submission
with its authority and exhibit bundle for initial testing. A separate discovery
profile can check the request/response/index workflow. Confirm actual registry
needs through separately authorised, permitted evidence rather than inventing them.

Limited TXT, DOCX and PDF intake is prepared with explicit extraction locations and
selected neutral-citation patterns. It is not court-approved or exhaustively
validated. Harden and independently assess one permitted input profile. Account
for failed extraction and unrecognised text. Add a supported neutral-citation
parser and an independent approved-source resolver, with retained source version,
retrieval date, provenance and explicit offline/not-found/ambiguous states.
Preserve publisher licences and avoid indiscriminate scraping. Test existing
citations that support the wrong proposition, not only invented citations.

Completion requires independently labelled permitted examples, a complete
input-to-report demonstration and visible unresolved questions. No automatic
rejection or good-law claim on an incomplete citation graph.

## Gate 2: evidence-grounded reasoning assistance

Implement optional claim/issue extraction, context-aware authority support,
contrary evidence, chronology/entity reconciliation and issue-to-relief coverage.
A model may propose review questions only. Each must carry input and source
anchors, source coverage, reasons and an abstention state. Source retrieval,
verbatim matching and semantic support remain separate checks.

A model provider, local model or accelerated host needs an independently verified
resource budget and approved data handling. None is activated or budgeted here.

## Gate 3: independent, blinded professional evaluation

Have authorised non-implementing reviewers label a held-out set before seeing
outputs. Include genuine difficult arguments, disputed facts, accurate quotations
used misleadingly, unavailable sources, older source versions, OCR failures,
legitimate alternatives, opposing accounts and self-represented submissions.

Report per-defect precision and recall, source/pinpoint coverage, abstention,
false alarms on valid submissions, disagreements and total workflow effort.
Include upload, mapping, verification, correction, reviewer handling and support.
Compare with ordinary manual review and any available approved tool. Predefine
acceptance criteria with the prospective court, especially false-positive limits.
Do not infer backlog reduction from an internal test count.

## Gate 4: institution-approved shadow pilot

With an authorised court or filing-system operator, run read-only alongside the
normal process. No submission is blocked or ranked for merits. Preserve filing
receipt times and originals. The court determines who can see a flag, respond to
it, override it and record a decision. Resolve confidentiality, privilege, public
records, data sovereignty, security, audit and procurement requirements locally.

Observe whether corrective work is reduced or merely shifted to filers/registry.
Stop or revise if false alerts, inequity or total workflow effort worsen.

## Gate 5: scoped integration and repeatable deployment

Only after a successful pilot, offer an on-premises or court-controlled service
with a versioned contract. A proposed adapter accepts a submission envelope and
returns findings plus source pointers. It does not assume an open court API or
write directly to the case docket. Idempotency, corrections, original version
history, authenticated reviews and audit evidence are required.

OASIS LegalXML ECF, including 5.01 (2023), is a relevant interoperability reference, not a claim that
every court supports it or that this alpha implements it. Use adapters only for
systems whose actual interfaces and authorisations are verified. GitHub remains
source control, not the case-document processing platform.

## Gate 6: another jurisdiction, not a global certification

Each jurisdiction pack needs an owner, local reviewer, source licence, effective
rule version, supported court/proceeding/document types, supported languages,
known exceptions and independent tests. A Singapore approval would not certify
England and Wales, an EU member state or a US jurisdiction. Local AI/data/legal
classification and institutional approval must be assessed for the actual use.

A plausible commercial path is an evaluation with a judicial technology unit or
an incumbent filing-system vendor, followed by scoped integration/support if
there is demonstrated value. No buyer interest, funding, sale or demand is
established. Do not send invitations or accept terms through this roadmap.
